# AGENTS.md — правила проекта «Дальшарик»

## Коммиты

Формат: `<prefix>: <описание на русском>`

- Префикс — английский, из списка Conventional Commits:
  - `feat:` — новая функциональность
  - `fix:` — исправление бага
  - `refactor:` — рефакторинг без изменения поведения
  - `docs:` — документация
  - `test:` — тесты
  - `chore:` — служебные изменения (сборка, конфиги, деплой)
  - `perf:` — оптимизация производительности
- Описание — краткое, на русском языке.
- Каждый коммит должен быть атомарным: одна логическая правка — один коммит.
- Перед коммитом: `npm run build` и `npm test` должны проходить.

## Модель веток (Git Flow)

- `main` — стабильная ветка, только релизы.
- `develop` — ветка интеграции, куда сливаются готовые фичи.
- `feature/<name>` — ветки новых функций, от `develop`.
- `hotfix/<name>` — срочные исправления, от `main`.
- `release/<version>` — подготовка релиза, от `develop`; после релиза мержится в `main` и `develop`.

Рабочий цикл:

1. От `develop` создаётся `feature/<name>`.
2. По завершении фича мержится в `develop`.
3. Когда `develop` готова к релизу — создаётся `release/<version>`.
4. Релиз тагается `v<version>` и мержится в `main` и `develop`.

## Релизы

- Версия — семантическое версионирование (major.minor.patch).
- Скрипты: `npm run release:patch|minor|major` — bump версии, коммит и тег `v<version>`.
- `npm run release:push` — пуш ветки и тегов в origin.
- Для MVP допускается релиз напрямую из `main` через `release:patch`.
