> **Соглашение:** при каждой функциональной правке добавляй запись в секцию `[Unreleased]` (разделы `### Добавлено` / `### Исправлено` / `### Изменено` / `### Удалено`). Перед релизом перенеси содержимое `[Unreleased]` в новую секцию `## [v<версия>] — <дата>`. ## [Unreleased]

### Добавлено

- Тихие часы: команда `/set_quiet_hours ЧЧ:ММ ЧЧ:ММ` (или `/set_quiet_hours off`) — в заданный интервал бот не публикует новые вопросы, а запланированные переносятся на время после окончания окна. По умолчанию включены с 00:00 до 08:00 по местному времени чата. ([#25](https://github.com/DrRocksoDevelopment/dalsharik_bot/issues/25))

### Изменено

- `/generate` по умолчанию генерирует 5 вопросов (раньше 10); количество по-прежнему задаётся аргументом (`/generate 10 history`). ([#26](https://github.com/DrRocksoDevelopment/dalsharik_bot/issues/26))
- `/generate` шлёт промежуточные статусы в личку: «темы подобраны», «факты собраны» — видно, на каком этапе идёт работа. Поиск фактов отчитывается по каждой теме по мере поступления (`[N/M] «тема» — K стр., всего X`). При ошибке парсинга ответа ИИ к сообщению добавляется превью ответа модели для отладки. ([#26](https://github.com/DrRocksoDevelopment/dalsharik_bot/issues/26))

### Исправлено

- `/generate` отклонял валидный ответ, если модель возвращала один вопрос объектом, а не массивом: `parseGeneratedText` теперь оборачивает одиночный объект с полями `question` и `answers` в массив. ([#26](https://github.com/DrRocksoDevelopment/dalsharik_bot/issues/26))
- `/generate` возвращал меньше вопросов, чем запрошено: добавлен цикл дозапросов (до 3 попыток) — если модель вернула N < count, бот запрашивает оставшиеся, исключая повторы. ([#26](https://github.com/DrRocksoDevelopment/dalsharik_bot/issues/26))
- `/generate` обрывался с «Promise timed out after 90000 milliseconds»: Telegraf по умолчанию даёт 90 секунд на обработку одного update, а полный цикл генерации (темы → поиск фактов → генерация) занимает дольше. Теперь лимит на обработку update настраивается через `HANDLER_TIMEOUT_MS` (по умолчанию 30 минут) и передаётся в Telegraf. ([#26](https://github.com/DrRocksoDevelopment/dalsharik_bot/issues/26))
- В карточке итогов и AI-сводке правильный ответ всегда подсвечивался как «A»: вариант ответа хранился с буквой-идентификатором (`correctAnswer`), а при перемешанном порядке показа буквы переставали совпадать. Теперь у каждого варианта флаг `correct: true/false`, буквы в карточке вычисляются по позиции, а связь «позиция в опросе → вариант вопроса» хранится числом (`optionMap`, `selectedOption`). Существующие данные мигрированы (бэкап `*.bak-answer-format`): `questions.json`, `questions_backup.json`, `polls.json`, `answers.json`, `metrics.json` и архивы импортов `data/imports/done/*.json`. ([#24](https://github.com/DrRocksoDevelopment/dalsharik_bot/issues/24))

## [v0.3.0] — 2026-08-14

### Добавлено

- Оценка вопроса из карточки итогов: кнопки «👍 Хорошо / 👌 Нормально / 👎 Плохо» на карточке (в т.ч. пустой и AI-сводке). Оценка сохраняется по (вопрос, пользователь), повторное нажатие перезаписывает её, счётчики обновляются прямо на кнопках. ([#22](https://github.com/DrRocksoDevelopment/dalsharik_bot/issues/22))
- Итоги (карточка, пустые итоги, сводка AI-шоу) прицепляются к исходному сообщению с вопросом: реплай-привязка (`reply_parameters`) и видимая ссылка `t.me/c/...` в тексте. Теперь при активном чатинге понятно, к какому вопросу относятся итоги. ([#20](https://github.com/DrRocksoDevelopment/dalsharik_bot/issues/20))

### Исправлено

- `/generate` падал с «невалидный JSON тем» и «модель не вернула текстовый ответ» на reasoning-моделях (например, `openai/gpt-5.6-luna`): модель тратила почти весь лимит токенов на «размышления» и обрывала JSON на середине. Теперь тем запрашивается ровно столько, сколько нужно, для генерации тем и вопросов рассуждение отключено (`reasoning: { enabled: false }`), а повреждённый/обрезанный JSON тем восстанавливается (одинарные кавычки, ключи без кавычек, хвостовые запятые, обрыв на полуслове). Если модель всё же исчерпала лимит на размышления — пользователь видит понятное сообщение. ([#23](https://github.com/DrRocksoDevelopment/dalsharik_bot/issues/23))
- `/generate` зависал после фазы поиска фактов (фаза 3 не стартовала): тело ответа читалось после `clearTimeout`, поэтому таймаут не покрывал чтение. Теперь таймер живёт до конца чтения тела, а таймаут Firecrawl поднят с 60с до 300с (`FIRECRAWL_TIMEOUT_MS`), OpenRouter — с 120с до 300с (`OPENROUTER_TIMEOUT_MS`).
- Генератор тем отдавал одинаковые темы на повторных запусках: OpenRouter кэшировал ответы. Для фазы тем кэш отключён заголовком `X-OpenRouter-Cache: false`.
- Генерация вопросов (фаза 3) обрезала JSON на лимите вывода 4096 токенов: на 10 вопросов deepseek не хватало. Лимит вывода для генерации вопросов поднят до 8192 токенов.
- Повторяющиеся темы событий: генератор тем получает блэклист уже использованных тем (до 100, из `event.title` всех вопросов пула), а до поиска фактов темы, точно или близко совпадающие с существующими (пересечение токенов, порог 0.66), отбрасываются — экономим запросы Firecrawl и меньше дедупликации. Вопросы с уже занятыми темами тоже отсекаются в `normalizeGenerated`.

## [v0.2.1] — 2026-08-12

### Исправлено

- Метрики AI-расхода считали стоимость по прайс-листу, а не по фактическому счёту: теперь основной показатель — фактический `usage.cost` из ответа OpenRouter (`total_cost_credits`), оценка по прайс-листу — только fallback. `/generate` и `/metrics` помечают сумму как «факт» или «оценка»; старые записи мигрируются при чтении.

## [v0.1.2] — 2026-08-10

### Добавлено

## [v0.2.0] — 2026-08-12

### Добавлено

- Режим «Шоу»: обычные опросы вместо викторин, голоса можно менять/отзывать («последний голос побеждает»), скоринг на финализации.
- AI-ведущий: разбор результатов «вживую» — план шоу через OpenRouter, строки дописываются в сообщение с драматическими паузами (`editMessageText`), после шоу — компактная карточка с вариантами, источниками и превью следующего события. Без ключа/модели/при ошибке — тихий фолбэк на статичную карточку.
- Команды: `/set_finalization ai|static` (админ группы), `/set_host_prompt` / `/reset_host_prompt` / `/host_prompt` (суперадмин, ЛС).
- Кастомный промпт генерации вопросов: `/set_generate_prompt <текст>` задаёт инструкцию ИИ, `/generate_prompt` показывает текущую (или стандартную), `/reset_generate_prompt` возвращает стандарт. Промпт полностью заменяет стандартный, сохраняя количество, категорию и чёрный список существующих вопросов.
- Метрики AI-расхода: usage каждой генерации (`/generate`) и каждого AI-шоу финализации записывается (`recordAiUsage`); `/metrics` показывает разбивку по сценариям — вызовы, токены, web-поиск и оценку стоимости в USD, плюс итог.
- Отдельная модель для генерации вопросов: `/set_generate_model <модель>`, сброс `/reset_generate_model`; по умолчанию используется общая модель (`/set_ai_model`). `/ai_status` показывает обе модели.
- Суперадминская рассылка `/broadcast <текст>`: отправка во все включённые чаты с паузой между сообщениями (1 сек), отчёт о доставленных и неудачных.
- `ChatConfig.subscription` (заглушка подписочного режима, пока ничего не гейтит).

### Изменено

- Итоги раунда без участников — компактное раскрытие правильного ответа без AI-шоу и стат-карточки.
- AI-шоу и `/generate` переиспользуют OpenRouter-клиент (`getOrCreateClient`): кеш цен модели больше не сбрасывается между вызовами, лишний тяжёлый запрос `GET /models` не выполняется на каждое шоу.
- `/set_answer_window` и `/set_interval`: суперадмин в группе может ставить любое значение от 1 сек; для админов групп минимум остаётся 60 сек.
- AI-ведущий: интрига до финала (правильный ответ только в последней строке), ведущему больше не передаются источники и время следующего события; паузы между репликами увеличены до 5 секунд; компактная карточка после шоу выводится через 2 секунды и по-прежнему содержит источники и время следующего события.

### Исправлено

- Чат больше не зависает при ошибке финализации poll: активный poll выходит из in-memory карты, повторная финализация планируется через `retryDelayMs`.
- `JsonStorage.update` больше не отбрасывает молча поля, отсутствующие в текущей записи: патч применяется целиком, что снимает тихие баги при эволюции схемы (например, новые поля конфига чата).
- Потеря ответов при подведении итогов: `publish()` возвращал poll без `telegramPollId` и `messageId`, из-за чего финализатор не мог закрыть опрос в Telegram и считал, что никто не ответил. Теперь публикация возвращает актуальную запись, а финализатор использует свежие данные из хранилища.
- Консольный и Telegram-логгер отбрасывали метаданные: описание ошибки в логах было не видно. Теперь поле `error` и остальные метаданные выводятся после сообщения.
- Запуск падал с «Бот ещё не создан» при настроенном `LOG_CHAT_ID`: Telegram-транспорт запрашивал бота в конструкторе до его создания. Теперь бот запрашивается лениво, при первой отправке лога.
- Все запросы к OpenRouter падали с ошибкой сети: заголовок `X-OpenRouter-Title` содержал кириллицу, недопустимую в HTTP-заголовках. Заменён на ASCII-транслит `Dalsharik`.

## [v0.1.1] — 2026-08-09

Первый тагированный релиз. Содержит результаты аудита кода и функциональность, накопленную с момента ветки `main` @ `9651d83`.

### Исправлено (надёжность и потеря данных)

- Опрос сохраняется со статусом `sending` до отправки в Telegram — нет «сирот» при падении между отправкой и сохранением; свип зависших `sending`/`finalizing` при старте.
- Начисление очков и серий — атомарно в одном `mutate` (нет потерь при параллельных ответах игрока).
- Финализатор: промежуточный статус `finalizing` → итоги → `completed`, ретрай после падения.
- Запись пула вопросов — через единую блокировку `JsonStorage` (backup, затем `mutate`).
- Исчерпание пула больше не ротируется вечно: окно последних 20 публикаций.
- Нет unhandled rejection при ошибке хранилища; `bot.launch()` обёрнут в try/await с корректным выходом.

### Исправлено (безопасность и ошибки)

- HTML-инъекция в `/config` — экранирование.
- Валидация ключей при `update` в json-хранилище; нормализация метрик при чтении.
- Глухие `catch` логируют warn/debug; `FileLock.acquire` не оставляет блокировку навсегда.
- Ленивое чтение env в `logger` (конфиг не читает env при импорте).
- `/help`: `/config` корректно помечен как суперадминский.
- Бэкфилл схемы и таймзоны для легаси-чатов; превью следующего события без `NaN`.

### Изменено (производительность)

- `/stats` читает questions.json один раз (`getAll()` + Map).
- Бэкап вопросов перезаписывается только при изменении пула.
- Перевод проекта на ESM (`type: module`).

### Добавлено

- Импорт вопросов из JSON-файла администратором (в т.ч. из `data/imports`), авто-фикс типа `history_next_event`, дедуп по тексту.
- Рейтинги группы и всех чатов, личная статистика (`/top`, `/top_global`, `/stats`).
- Серии и рекорд чата в итогах, превью следующего события.
- Сбалансированный выбор вопросов и сложность от времени суток.
- Управление ботом только для админов; команда `/metrics` для суперадмина.
- Расширенный сбор метрик: daily-серия, явка в раундах, размерности вопросов, медианы скорости, first/last_seen.
- Повторный `/start` не сбрасывает таймер и сообщает время следующего вопроса.
- Все типы вопросов включены по умолчанию для существующих чатов.

### Зависимости и сборка

- vitest 2.x → 4.x — устранены critical/high уязвимости (vite/esbuild/vite-node), `npm audit`: 0 уязвимостей.
- `@telegraf/types` явно в dependencies.
- `tsconfig` `rootDir: "src"` — сборка больше не кладёт тесты в `dist/`.

### Тесты

- 27 файлов, 182 теста, покрытие ~87% (statements) через `@vitest/coverage-v8` (`npm run test:coverage`).
- Покрыты: гонки параллельных ответов, сбой send-before-persist, `reloader.start()` без dataDir, бот и команды, логирование, запуск `index.ts` (отсутствие env, ошибка launch, graceful shutdown).
- Стабилизирован тайминг тестов планировщика.
