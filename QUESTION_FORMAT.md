# Формат вопросов «Дальшарика» (JSON) — памятка для ИИ

> Эта памятка предназначена для генерации вопросов нейросетью. Скопируйте разделы
> «Суть», «Схема», «Правила» и «Пример» в промпт — и попросите модель вернуть
> 10–20 вопросов строго в заданном JSON-формате, без пояснений и markdown-обёрток.

## 1. Суть формата

Бот-викторина «Что было дальше?» задаёт вопрос по **реальному событию**:

1. Пользователю показывается краткий контекст события (`event.context`).
2. Задаётся вопрос «Что произошло **дальше**?» (`question`).
3. Даётся 4 варианта ответа (`answers`), из них ровно один верный (`correctAnswer`).
4. После закрытия опроса показывается объяснение (`explanation`) и источники (`sources`).

Ключевое: правильный ответ должен быть **прямым продолжением** события из контекста,
а не пересказом уже известных фактов. Вопрос «когда/кто/где» — не в этом формате.

## 2. JSON-схема

```json
{
  "id": "event_000001",
  "type": "historical_next_event",
  "category": "history",
  "difficulty": 2,
  "eventDate": "1969-07-20",
  "event": {
    "title": "Высадка Apollo 11 на Луну",
    "context": "20 июля 1969 года Нил Армстронг первым в истории ступил на поверхность Луны."
  },
  "question": "Что сделали астронавты сразу после выхода на поверхность Луны?",
  "answers": [
    { "id": "A", "text": "Установили флаг США и собрали образцы лунного грунта" },
    { "id": "B", "text": "Срочно вернулись в модуль из-за утечки кислорода" },
    { "id": "C", "text": "Запустили с Луны спутник связи" },
    { "id": "D", "text": "Дождались прибытия советского лунохода" }
  ],
  "correctAnswer": "A",
  "explanation": "Армстронг и Олдрин провели на поверхности около 2 часов: установили флаг, развернули научные приборы и собрали порядка 21,5 кг образцов грунта.",
  "sources": [
    "https://www.nasa.gov/mission_pages/apollo/apollo11.html",
    "https://www.history.com/this-day-in-history/apollo-11-lands-on-the-moon"
  ],
  "createdAt": "2026-08-09T00:00:00.000Z"
}
```

### Описание полей

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `id` | string | да | Уникальный идентификатор. Формат `event_NNNNNN`, глобально уникален |
| `type` | string | да | Тип вопроса, см. список ниже |
| `category` | string | да | Категория, см. список ниже |
| `difficulty` | number | да | Целое число от **1** до **5** (1 — просто, 5 — сложно) |
| `eventDate` | string | да | Дата события, ISO `YYYY-MM-DD` |
| `event.title` | string | да | Краткое название события (1 строка) |
| `event.context` | string | да | 1–3 предложения: что известно к моменту вопроса |
| `question` | string | да | Вопрос «Что было дальше?». Тексты вопросов не должны повторяться в файле |
| `answers` | array | да | Минимум **4** объекта `{ id, text }` |
| `answers[].id` | string | да | Буква варианта: `A`, `B`, `C`, `D`, ... — уникальны внутри вопроса |
| `answers[].text` | string | да | Текст варианта (непустой) |
| `correctAnswer` | string | да | `id` верного варианта — **обязательно присутствует** среди `answers` |
| `explanation` | string | да | Объяснение с фактами и датами, 2–4 предложения |
| `sources` | array | да | Непустой массив строк — реальные URL источников (1–2 шт.) |
| `createdAt` | string | да | ISO-дата. **При импорте заполняется автоматически**, можно не указывать |
| `nextEventId` | string | нет | Резерв для будущих цепочек событий. Сейчас не заполняется |

## 3. Допустимые значения

**`type`** (соответствует категории):
- `historical_next_event` — история
- `scientific_next_event` — наука
- `technology_next_event` — технологии
- `business_next_event` — бизнес/экономика
- `culture_next_event` — культура
- `geography_next_event` — география

**`category`**: `history` | `science` | `technology` | `culture` | `geography`

**`difficulty`**: целое от 1 до 5. Ориентир:
- 1–2 — широко известные события, очевидный ответ после подсказки;
- 3 — известное событие, но продолжение требует знания;
- 4–5 — редкие детали и неочевидные продолжения.

## 4. Правила валидации (проверяются ботом)

Импорт **отклонит** вопрос, если нарушено любое из правил:

1. `id` — непустая строка; id не должны дублироваться внутри одного файла.
2. `type` и `category` — строго из списков выше (иначе вопрос отклоняется).
3. `difficulty` — целое число 1..5.
4. `eventDate`, `event.title`, `event.context`, `question`, `explanation` — непустые строки.
5. `answers` — не менее 4 элементов; `id` вариантов уникальны; у каждого есть текст.
6. `correctAnswer` — должен быть одним из `answers[].id`.
7. `sources` — непустой массив строк.
8. Тексты вопросов не должны повторяться в одном файле.

## 5. Требования к содержанию

- Все события и факты — **реальные и проверяемые**. Никакого вымысла.
- Контекст даёт минимум информации: только то, что известно «до» события.
- Вопрос должен быть сформулирован про **следующий шаг/событие**, а не про сам факт.
- Ровно **один** верный вариант; остальные — правдоподобные, но **однозначно ложные**,
  примерно одинаковой длины и стиля с верным (чтобы ответ нельзя было угадать по форме).
- Дистракторы не должны содержать абсурд или анахронизмы.
- Объяснение — факты + даты + почему верен ответ; пишется после размышления.
- Источники — реальные и доступные: Wikipedia, музеи, NASA, Britannica, гос. сайты и т.п.
- Избегайте: неоднозначных фактов, спорных трактовок, вопросов про будущее,
  «угадай по формулировке» вариантов, ответов, которые легко вычислить логически.

## 6. Формат вывода ИИ

- Вариант 1: обычный JSON-массив `[ { вопрос1 }, { вопрос2 }, ... ]`.
- Вариант 2: объект `{ "questions": [ ... ] }`.
- Без markdown-обёрток, без комментариев, без пояснений — **только валидный JSON**.
- Рекомендуемый размер пачки: **10–20 вопросов** за ответ.
- Старайтесь покрывать разные категории; сложность — преимущественно 2–3,
  редкие сложные (4–5) — в меньшинстве.

## 7. Типичные ошибки (так делать нельзя)

```jsonc
// ошибка: difficulty строкой вместо числа
{ "difficulty": "3" }
// ошибка: тип не из списка
{ "type": "space_next_event" }
// ошибка: нет sources
{ "sources": [] }
// ошибка: correctAnswer не среди вариантов
{ "answers": [{ "id": "A", "text": "..." }], "correctAnswer": "Z" }
// ошибка: вопрос не про «дальше», а про сам факт
{ "question": "Кто высадился на Луну в 1969 году?" }
// ошибка: нереалистичный дистрактор (должен быть правдоподобным)
{ "text": "Дождались прибытия советского лунохода" }
```

## 8. Загрузка в бота

1. Сохраните ответ ИИ в файл `questions.json`-вида (или просто сохраните как `.json`).
2. Админ отправляет файл боту **в личных сообщениях**.
3. Бот валидирует вопросы, добавляет валидные без дублей прямо в активный пул
   и присылает отчёт: импортировано / переименовано / пропущено / ошибки.
4. Локальная проверка пула перед импортом: `npm run validate-questions`
   (валидирует `data/questions.json`).

> `id` и `createdAt` из файла сохраняются как есть; при отсутствии `createdAt`
> бот заполнит его автоматически. Если `id` уже есть в пуле — вопрос **не
> пропускается, а переименовывается** в свободный `event_NNNNNN` (об этом будет
> сказано в отчёте). Вопрос с текстом, который уже есть в пуле, пропускается.
> Опечатка `history_next_event`/`science_next_event` (вместо
> `historical_next_event`/`scientific_next_event`) исправляется автоматически.
